## 调用与审批模型

- **只读工具（`readonly = true`）**：自动放行，无需用户确认。
- **写/执行类工具（`readonly = false`）**：按会话审批策略请求确认，首次调用或每次调用均需用户授权（取决于设置）。
- 文件工具**没有沙箱**：绝对路径可指向磁盘任意位置，相对路径落在会话的**写入目录**（项目目录，或未指定时的自动会话工作区）。落在写入目录之外的调用会在审批卡上高亮提醒用户——不拦截，只让人看见。详见「文件工具」一节。

## 文献工具

### `paper_search`

在本地论文图书馆中通过标题、作者、关键词或摘要进行全文搜索。省略 `query` 时按导入时间列出最近的论文；可按收藏夹/标签名过滤。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `query` | string | ❌ | 搜索词；省略或留空时按导入时间列出最近的论文 |
| `collection` | string | ❌ | 收藏夹名称，只返回该收藏夹内的论文 |
| `tag` | string | ❌ | 标签名称，只返回带该标签的论文 |
| `limit` | integer | ❌ | 最大返回条数，默认 5，最大 50 |
| `offset` | integer | ❌ | 跳过的条数，默认 0 |

### `search_library`

在**已索引**的论文全文中检索最相关的段落（关键词 FTS5；配置了真实 embedding 后端时叠加向量召回并做 RRF 融合）。返回论文标题、页码范围与章节路径，便于直接引用或再用 `paper_read` 取上下文。找具体事实/方法/论断时用它；需要完整论证时用 `paper_read`。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `query` | string | ✅ | 检索词（用论文本身的语言，关键词优于长问句） |
| `limit` | integer | ❌ | 返回段落数，默认 8，最大 30 |
| `include_references` | boolean | ❌ | 是否检索参考文献/附录，默认 `false` |

### `paper_read`

获取论文的元数据、摘要及分页文本块。默认不返回正文块，可通过 `include_chunks=true` 开启。每个块带**章节路径**与**块类型**（prose/heading/caption/reference）；参考文献/附录会**打标不隐藏**（输出中标为 `references/appendix`），可正常读取——检索侧默认不召回它们。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `paper_id` | string | ✅ | 论文 UUID |
| `include_chunks` | boolean | ❌ | 是否返回正文块，默认 `false` |
| `offset` | integer | ❌ | 起始块索引，默认 0 |
| `limit` | integer | ❌ | 返回块数，默认 20，最大 50 |
| `max_chars` | integer | ❌ | 每块最大字符数，默认来自设置（2500 ≈ 整块） |

### `paper_snapshot`

把论文某页的一块区域渲染成 PNG 并返回路径——模型拿到路径后**必须在回复正文用 `![](path)` 嵌入**，气泡会渲染缩略图供用户点击放大。`label`、`rect`、`region` 互斥；三者都省略时截取整页。

指定图表优先只传 `label`（如 "图3"、"Fig. 2"、"Table 1"）。后端结合索引中的图注位置与 PDF 页面的图片、矢量、文本几何信息，按栏和相邻正文边界计算完整裁剪区域；低置信度时若配置了视觉模型，会先在完整页面上定位再高清裁剪。`label` 模式默认包含图注。`rect` 是显式 "x0,y0,x1,y1"（PDF points、y-up），只能使用用户或工具已提供的坐标，模型不得猜测。`region`（top/middle/bottom/full）仅用于有意的粗略页面截图。

结果包含实际 `rect`、页面尺寸、`crop_source`、`confidence` 和 `includes_caption`，便于追踪和核验。若该文献的图表索引缺失（功能上线前导入的老文献从未回填），工具会先就地补建索引再重试 `label`，并在结果里给出 `index_note`；补建后仍为空说明这份 PDF 没有可识别的图表图注（既无匹配的 `Figure/Table` 标题也无可用图片对象），此时才退到 `region`，且必须如实说明是粗略区域。`analyze=true` 时用会话配置的多模态模型解读最终截图；主 Agent 需要把图中内容作为分析依据时必须开启，只有图片路径不代表模型看到了图片。视觉解读仅可依据可见内容，裁剪置信度低或关键内容缺失时必须说明并用 `paper_read` 核验，不得补全不可见数据。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `paper_id` | string | ✅ | 论文 UUID（同 `paper_read`） |
| `page` | integer | ❌ | 页码（1 起）；给了 `label` 时可省略（全篇搜索该标签），默认 1 |
| `label` | string | ❌ | 图表 caption 标签；指定图表时优先使用，不与 rect/region 混用 |
| `rect` | string | ❌ | 显式裁剪矩形 "x0,y0,x1,y1"（PDF points，y-up）；不得猜坐标 |
| `region` | string | ❌ | 粗略页面区域 top / middle / bottom / full |
| `include_caption` | boolean | ❌ | `label` 截图是否包含图注，默认 `true` |
| `analyze` | boolean | ❌ | 用多模态模型解读截图并返回描述，默认 `false` |
| `analyze_prompt` | string | ❌ | 自定义视觉解读提示词（仅 analyze=true 时生效；可见性约束仍生效） |

### `paper_import`

将本地 PDF 文件导入图书馆。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file_path` | string | ✅ | PDF 文件的绝对路径 |

## 网络工具

### `web_fetch`

抓取指定 URL 的内容，HTML 会被转换为纯文本。遵守配置的 LLM 代理。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `url` | string | ✅ | 要抓取的 URL |

### `web_search`

按「设置 → 网络搜索」中配置的**引擎链**依次搜索：一次调用内按顺序尝试已启用的引擎，首个返回结果的引擎生效（自动回退，不浪费对话轮次）。支持 Bing（国内直连，默认首位）、DuckDuckGo（需代理/海外网络）、Tavily 与 Brave Search（需 API Key）、SearXNG（自托管实例）。返回标题、URL 和摘要，并标注实际命中的引擎。遵守会话/全局代理配置。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `query` | string | ✅ | 搜索词 |
| `max_results` | integer | ❌ | 最大返回条数，默认 6，最大 10 |

## 浏览器工具

L1 浏览器自动化：经 CDP 驱动**本机真实的 Chrome/Edge**（不内嵌浏览器），让智能体完成需要登录态或 JS 渲染的网页任务——典型场景是"登录学校图书馆/知网检索并下载文献"。核心策略：复用真实浏览器指纹与登录态，遇到人机验证移交人类，不做反检测对抗。

**使用约束（模型与用户都应知道）：**

- 浏览器是 **headed 窗口**，要求桌面已登录且**未锁屏**；锁屏时操作会失败，远程（微信/飞书）发起浏览器任务前需确认电脑前有人或屏幕可用。
- 三种供给模式（`browser_connect` 的 `mode`）：`persistent`（默认，思库管理的独立持久 profile，站点登录态长期保留——Chrome 136+ 拒绝在默认用户 profile 上开 CDP，故用独立 profile）、`temporary`（干净临时 profile，一次性任务）、`attach`（附加到用户以 `--remote-debugging-port` 启动的浏览器，**永不关闭**它）。
- **快照即眼睛**：`browser_snapshot` 把可见可交互元素映射为编号 ref（`[3-12]`），click/type 都按 ref 操作；DOM 变化后 ref 失效，工具会明确报错要求重新快照。截图（`browser_screenshot`）只在视觉/布局相关时使用。
- **人机验证**：navigate/click 后自动检测（reCAPTCHA/hCaptcha/Cloudflare/GeeTest/Arkose），命中即在结果中警告；`browser_captcha_wait` 发桌面通知并把标签页置前，轮询等待用户手动完成（默认 5 分钟，可续等）。绝不尝试绕过验证。
- 产出落盘在会话写入目录的 `screenshots/`、`downloads/`；下载得到的 PDF 可直接 `paper_import` 入文献库。
- 设置页「浏览器」可覆盖可执行文件路径与默认连接模式；应用退出时自动关闭思库启动的浏览器。

### `browser_connect`

启动或附加浏览器。幂等：已有健康连接直接复用；连接失活（用户关了窗口）自动重建。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `mode` | string | ❌ | `persistent`（默认，可用设置页改默认值）/ `temporary` / `attach` |
| `port` | integer | ❌ | attach 模式的调试端口，默认 9222 |

### `browser_close`

关闭连接。思库启动的浏览器会被关闭（persistent profile 保留、temporary 删除）；attach 模式只断开连接。

### `browser_navigate`

活动标签页导航到 URL，等待 load 事件（30 秒超时）。无 scheme 时自动补 `https://`。返回最终 URL 与标题；若检测到人机验证会附加警告。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `url` | string | ✅ | 目标 URL |

### `browser_tabs`

列出（list）/切换（switch）/关闭（close）标签页。switch/close 用 list 输出的 1 起序号；switch 同时把窗口置前。新打开的 tab（target=_blank）在这里切换。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | string | ✅ | `list` / `switch` / `close` |
| `index` | integer | ❌ | tab 序号（switch/close 必填） |

### `browser_wait`

等待 CSS 选择器出现（250ms 轮询）或定时休眠。只读。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `selector` | string | ❌ | 等待的 CSS 选择器；省略则仅休眠 |
| `timeout_ms` | integer | ❌ | 默认 10000，最大 60000 |

### `browser_snapshot`

DOM 快照：返回页面标题/URL 与全部可见可交互元素（链接/按钮/输入框/select/role=button 等），每个元素带 `[代-序号]` ref。上限 400 个元素，超出提示分步/滚动。只读。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `include_text` | boolean | ❌ | 同时返回页面可见正文（前 4000 字符），默认 false |

### `browser_click`

按 ref 点击（真实鼠标事件，JS 处理器正常触发）。点击后报告 URL 变化与新开 tab，并做人机验证检测。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `ref` | string | ✅ | 快照中的元素 ref，格式 `<代>-<序号>` |

### `browser_type`

按 ref 输入文本（真实按键，自动完成/校验处理器正常触发）。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `ref` | string | ✅ | 元素 ref |
| `text` | string | ✅ | 输入内容 |
| `clear` | boolean | ❌ | 先清空（触发 input/change 事件，兼容 React 等框架），默认 false |
| `press_enter` | boolean | ❌ | 输入后按回车，默认 false |

### `browser_scroll`

滚动页面或把 ref 元素滚入视野，报告滚动位置与是否到底。只读。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `direction` | string | ❌ | `up` / `down`（默认）/ `top` / `bottom` |
| `ref` | string | ❌ | 元素 ref（优先于 direction） |
| `amount` | integer | ❌ | 滚动像素，默认 700 |

### `browser_screenshot`

截图存 PNG 到 `screenshots/`，返回路径（可接 `read_media_file` 视觉解读）。只读。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `full_page` | boolean | ❌ | 整页截图（默认 false，仅视口） |
| `filename` | string | ❌ | 文件名，默认自动 `page-<时间戳>.png` |

### `browser_download_pdf`

PDF 产出，三个 action：

- `fetch`：抓取当前标签页已打开文档（典型场景：点击 PDF 链接被 Chrome 内置查看器打开、未触发下载）的原始字节。原理：在页面上下文内 `fetch(location.href)` 重取文档并 base64 回传——PDF 导航的顶层 document origin 即 PDF URL 自身，故同源；走浏览器自身网络栈，代理/Cookie/企业 CA 自动生效。以 `document.contentType === 'application/pdf'` 判定 PDF 页（arXiv 这类无 `.pdf` 后缀的 URL 也覆盖）。字节头非 `%PDF` 时输出警告。
- `download`：先把浏览器下载目录定向到会话 `downloads/`，点击指定 ref 触发下载，轮询等待完成（`.crdownload` 消失），可选改名。快速失败：点击后标签页 `document.contentType` 变为 `application/pdf`（被内置查看器打开）时立即报错并提示改用 `fetch`。
- `print`：当前页渲染为 PDF（带背景）。仅限 HTML 页面——对内置 PDF 查看器页只会截到查看器 UI。

PDF 结果提示可接 `paper_import`。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `action` | string | ✅ | `fetch` / `download` / `print` |
| `ref` | string | ❌ | download 必填：触发下载的元素 ref |
| `url` | string | ❌ | fetch 可选：文档 URL，默认取当前标签页 URL |
| `filename` | string | ❌ | 输出文件名 |
| `timeout_ms` | integer | ❌ | 下载/抓取等待上限，默认 60000，最大 300000 |

### `browser_captcha_wait`

人机验证人工接管。检测到验证时调用：桌面通知 + 标签页置前，1 秒轮询直到验证消失；超时如实报错，可再调一次继续等。支持 reCAPTCHA / hCaptcha / Cloudflare Turnstile / GeeTest / Arkose。只读。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `timeout_ms` | integer | ❌ | 默认 300000（5 分钟），最大 600000 |

## 文件工具

文件工具**没有沙箱**，这是刻意的：`bash` 本来就不受约束（只设 cwd，一条 `cd`/重定向就能去任何地方），一个只拦文件工具的"沙箱"从来不是边界，只会让模型在需要临时目录、别的仓库或用户 Downloads 时白撞一轮 `outside working directory`。真正的闸门是审批弹窗。

保留下来的是有用的一半——**写入目录**（相对路径的默认落点）：

- **绝对路径**：原样使用，可指向磁盘任意位置。
- **相对路径**：基于会话的写入目录解析。写入目录 = 会话绑定的项目目录；未绑定（或目录已失效且无法经项目自愈）时，自动使用 **会话工作区** `app_data_dir/agent_workspaces/<session_id>`（按会话隔离，首次使用时创建；可在会话设置的"写入目录"处**打开 / 复制路径 / 清空**）。
- **绝不用进程当前目录当基准**：桌面应用从资源管理器/开始菜单启动时它常是 `C:\Windows\System32` 之类的位置——文件曾因此被写到那里，却把用户给的相对路径原样回报，模型误以为已落盘。因此在没有写入目录时，相对路径会被明确拒绝并要求改用绝对路径。
- **越界只提醒不拦截**：写入落在写入目录之外时，审批卡会显示醒目告警（`⚠ 该路径不在写入目录内，请确认这是你要的位置`；带 `cwd` 的 bash 则是 `⚠ 该命令在写入目录之外运行`），由用户决定是否放行。
- 每轮对话的系统提示都会告知模型本会话的写入目录（或"已回退到会话工作区"），模型无需靠试错发现。

### `file_read`

读取文本文件，支持按行偏移分页。读取会记录该文件当前的（大小 + mtime）快照，`file_write` 的整文件覆盖以此判断"是否看过当前内容"。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `path` | string | ✅ | 文件路径（绝对路径任意位置，或相对写入目录） |
| `line_offset` | integer | ❌ | 1-based 起始行；负数从末尾计数，默认 1 |
| `n_lines` | integer | ❌ | 返回最大行数，默认 200，最大 1000 |

### `file_list`

列出目录下的文件和子目录。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `path` | string | ❌ | 目录路径，默认写入目录 |

### `send_file_to_user`（远程专用）

只有在**远程 IM 会话 + 私聊 + 「全部」授权 + 微信渠道**四个条件同时成立时才会注册（`run_agent_turn` 内按 `session.context` 判断），本机对话与群聊都看不到这个工具。

它**不自己发送**：把文件登记进本轮的出站队列（`OutboundFile`），回合结束时由 `run_agent_turn` 序列化进 assistant 行的 `attachments`，再由路由层上传投递——保证"对话里看到的"和"手机上收到的"是同一份记录（`docs/remote-channels.md` §7.1）。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `path` | string | ✅ | 文件路径（绝对路径，或相对会话写入目录） |
| `caption` | string | ❌ | 随文件前的一条说明文字 |

限制：仅允许会话工作区、`remote_downloads/`、`remote_outbox/`、桌面/下载/文档目录；单文件 ≤25MB、每回合 ≤5 个且合计 ≤50MB；按 `path+size` 去重。

### `file_write`

创建、覆盖或追加文本文件，自动创建父目录。修改已有文件时应优先使用 `file_edit`（局部替换），避免全量覆盖。写入是**原子替换**（同目录临时文件 + rename，并保留原文件权限位），因此不会出现"截断到一半"的半成品文件。

**缺省 `mode` 不是"覆盖"**：不传 `mode`（或传空串）表示"新建" —— 目标不存在、或存在但为空时正常写入；**目标已存在且非空则直接报错**，不会清空文件，模型需改用 `file_edit` 或显式传 `mode: "overwrite"`。覆盖因此永远是一次显式决定；`mode` 传成非字符串（`null`、数字、对象）会报错，不会退化成覆盖。

**`mode: "overwrite"` 还要求"看过"该文件**：本次会话里用 `file_read` 读过它，或它本来就是本会话自己写的；否则报错要求先读。文件在读过之后被外部改动（大小/修改时间变了）也会被拦下——避免拿旧认知覆盖新内容。`append` 不截断任何内容，因此不需要这道门。

`append` 在需要时会自动补一个换行分隔符：若目标文件非空且结尾没有 `\n`，先写一个 `\n` 再写内容（返回值会说明），避免把新内容黏到最后一行上——对脚本/配置是致命的。

返回值形如 `Created /abs/x.ts (1.2 KB, 42 lines)` / `Overwrote /abs/x.ts (was 1.0 KB, now 1.2 KB, 42 lines)` / `Appended 120 B (3 lines) to /abs/x.ts (now 1.4 KB)`：**一律是绝对路径**，且用字节数（便于与 `ls -l` / `wc -c` 交叉核对）。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `path` | string | ✅ | 文件路径 |
| `content` | string | ✅ | 写入内容 |
| `mode` | string | ❌ | `overwrite` 或 `append`；不传 = 新建（目标已存在且非空则报错） |

### `file_edit`

精确替换文件中唯一出现的子串；如需替换多处，可设置 `replace_all=true`。与 `file_write` 一样是**原子替换**（同目录临时文件 + rename，保留原文件权限位），且编辑成功后该文件即被视为"已看过"，后续 `mode: "overwrite"` 无需再读。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `path` | string | ✅ | 文件路径 |
| `old_string` | string | ✅ | 待替换文本 |
| `new_string` | string | ✅ | 替换后文本 |
| `replace_all` | boolean | ❌ | 是否替换所有匹配，默认 `false` |

### `file_grep`

在工作目录的文本文件中搜索子串（区分大小写，非正则），返回匹配行及行号。结果达到 `max_results` 或扫描文件数达到内部上限（500）时会在输出末尾标注截断，此时应缩小范围重试。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `pattern` | string | ✅ | 搜索子串 |
| `path` | string | ❌ | 文件或目录范围 |
| `max_results` | integer | ❌ | 最大匹配行数，默认 50，最大 100 |

### `file_glob`

按 glob 模式列出文件，支持 `*`、`?`、`**`（`**/` 可匹配零层目录，如 `**/*.rs` 同时命中根目录与子目录下的文件）。

| 参数 | 类型 | 必填 | 说明 |

| `pattern` | string | ✅ | glob 模式 |
| `path` | string | ❌ | 可选起始子目录 |

## 长期记忆工具

每个会话拥有两份长期记忆文档（Markdown，随会话跨轮次存在），用户可在输入区大脑按钮的「全局 / 本机」两个标签页查看/编辑，或通过消息气泡的「打标」把助手回复追加到全局记忆：

- **全局记忆**（`agent_memories`，CRR 跨设备同步）：用户偏好、项目约定、领域知识、经验与决策。
- **本机记忆**（`agent_memories_local`，故意不同步）：仅适用于当前设备的事实（操作系统、已装软件及版本、绝对路径、硬件）。这类事实若同步会在其它设备上被当成真值注入，因此物理隔离在另一张表里。

注入时本机记忆带有「仅适用于设备「<设备名>」」标头，模型不会把它套用到其它设备。

### `memory_read`

读取本会话的长期记忆全文（全局 + 本机两段）。只读。

无参数。

### `memory_write`

写入长期记忆。覆盖写会先自动快照旧内容（可恢复）。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `content` | string | ✅ | 要写入的内容 |
| `mode` | string | ❌ | `append`（默认，追加一段）或 `overwrite`（整体替换） |
| `scope` | string | ❌ | `global`（默认，跨设备同步）或 `device`（仅此设备，记本机环境事实） |

`append` 模式会自动为内容加上 `## YYYY-MM-DD` 日期小节标题（内容本身以 `#` 开头则不重复添加），保证每段记忆可追溯时间。

### `memory_recall`

检索本会话的**历史对话原文**（与长期记忆文档不同：memory_read/write 管「沉淀的结论」，recall 管「说过的话」）。当历史超出「最大记忆轮次」窗口或因上下文预算被省略时，模型可用它回查完整内容。只读。

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `query` | string | ❌ | 关键词，空格分隔（AND、不区分大小写）；留空则按时间范围浏览 |
| `role` | string | ❌ | `user` / `assistant`，缺省不限 |
| `from` / `to` | string | ❌ | 时间范围，如 `2026-10-08`（to 的裸日期覆盖当天全天） |
| `include_steps` | boolean | ❌ | 同时返回每个命中助手轮次的工具调用（名称/参数/结果预览），默认 false |
| `limit` | number | ❌ | 返回条数上限，默认 20、最大 50，按时间正序展示 |

单条消息内容上限 1200 字符、整体输出上限约 8000 字符，超限提示缩小范围。

配套机制（无需模型介入）：当历史被轮次窗口截断时，系统提示词会自动注入一段「截断清单」——被省略部分的轮数、时间范围和每条用户消息首行——供模型定位后调用本工具回查；token 预算截断时也会注入一行提示。

## 技能工具

技能（插件）是**会话级挂载**的能力包：未挂载的技能对模型完全不可见（描述不占上下文）；挂载后注册为 `skill_<name>` 工具，调用时才注入 SKILL.md 正文。

- **安装**：对话页左侧「插件」弹窗中通过**文件夹**或 **zip 压缩包**导入（目录需包含带 `name` 前言的 `SKILL.md`），同名冲突报错不覆盖。
- **挂载**：插件详情对话框「挂载到当前会话」，或会话「个性设置 → 技能挂载」多选。
- **多文件技能**：调用返回中附带技能目录的绝对路径与文件清单，SKILL.md 可用相对路径引用自带脚本/模板，模型经 `bash` 等工具执行。
- **AI 审查**：插件卡片上的「AI 审查」对技能做静态安全扫描（危险命令/提示词注入/敏感路径/网络外联/混淆模式）与依赖探测（git/python 包等实测可用性），再交由无工具的「安全审查」智能体做语义级分析；结论按内容指纹存档，技能被修改后自动失效为「待复审」。

| 属性 | 说明 |
|------|------|
| 工具名 | `skill_<name>`（`name` 取自 SKILL.md 前言，自动规范化为合法工具名） |
| 只读 | ✅ |
| 参数 | `args`（string，可选）：传递给技能的上下文或参数 |
| 行为 | 调用时将技能内容 + 技能目录路径 + 文件清单注入对话，作为该领域任务的专用指令 |

## 输出截断与思考续传

单轮输出额度（`max_tokens`）耗尽时，引擎分两种情况处理，目的都是**不把截断悄悄当成完整答案**：

**1. 已有正文被截断**（`finish_reason=length` 且有可见文本）——自动续写：

- 把已写出的半截正文作为 **assistant 消息**回灌，再补一条指令「从断点接着写，不要重复已写内容、不要重新开头、不要加前言」，然后用**翻倍后的额度**重发一次；
- 增量按**逐字拼接**回完整回答（不加段落分隔、不 trim），因此用户看到的是一篇连贯的答案；
- 最多自动续写 2 次（`MAX_CONTINUATIONS`），额度每次翻倍并夹在 `[1024, 131072]` 之间（避免 0 或荒谬值）；
- 若截断发生在**生成工具调用**的过程中，则不回灌半截文本（那串 JSON 已经不可用），改为提示「重新输出完整工具调用，不要重复已写正文」。

**2. 思考占满额度、正文一个字都没有**（`finish_reason=length` 且无可见文本）——问用户是否调大后重试：

- 通过 `ask_user` 询问「调大到 N 重试 / 不重试」（同一回合内最多 3 次翻倍）；拒绝或用尽时，持久化的是一条明确说明，而不是空消息；
- 重试时把**被打断的思考草稿尾部**（最多 6000 字符）放进 user 消息交回模型，明确要求「接着它继续推断，不要重述、不要从头再来」——避免模型拿着翻倍后的额度把同一段长思考重新烧一遍；
- 草稿走 `user` 角色而不是 assistant：该轮没有产生任何 assistant 消息（正文为空），而空 content 的 assistant 消息会被部分服务商拒绝；同时绕开「中途 system 消息」导致模板 500 的坑。

**思考回传（`reasoning_content`）**：DeepSeek 思考模型在**带 `tools` 的请求**里必须把历史每一轮的 `reasoning_content` 完整回传，否则 API 返回 **400**；回传后会被拼进上下文，这正是"接续思考"的官方机制。因此：

- 本应用在同一回合内会把每轮 assistant 消息的思考一起回传（工具轮也带）；
- 跨回合则把该回合的思考（各轮拼接、上限 8000 字符、保留尾部）随 assistant 记忆记录持久化，下个回合重新回传；
- 默认**只对 DeepSeek 官方端点开启**（`provider=deepseek` 且 `base_url` 含 `api.deepseek.com`），其他厂商一般不需要甚至会拒绝该字段；每个智能体的模型配置里有「回传思考内容」三态开关：自动 / 总是 / 从不。
