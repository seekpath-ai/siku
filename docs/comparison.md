# 思库适合谁：与常见工具的关系

> 这是一张按场景选择工具的说明。不同工具解决的问题不同，思库的定位是**个人科研场景下的本地知识工作台**。

## 一句话定位

| 工具 | 最主要解决的问题 |
|---|---|
| **思库 Siku** | 在同一个本地知识库里读 PDF、做笔记、检索文献，并让 Agent 操作本地文件/浏览器/脚本 |
| Obsidian | 以 Markdown 为中心的个人知识库与双链笔记 |
| Zotero | 文献元数据管理与论文引用/写作 |
| Notion | 团队协作、数据库与文档 |
| ChatGPT / Claude 等通用助手 | 通用问答、写作与代码辅助 |

## 按需求选择

| 你的需求 | 更适合 |
|---|---|
| 纯 Markdown 双链笔记、插件生态 | Obsidian |
| 论文引用管理、Word/LaTeX 写作、文献库规范 | Zotero |
| 团队协作、数据库、权限与共享页面 | Notion |
| 个人科研：PDF 阅读 + 引用回跳 + 笔记 + AI + 本地数据 | **思库** |

## 思库的不同点

### 1. PDF 与引用是一等公民

PDF 是阅读和引用的核心对象：

- 本地解析全文、分页、章节路径
- Agent 读全文，检索默认跳过参考文献/附录
- 回答带 chunk 引用，点击回原文并高亮
- 笔记里的引用也能回到 PDF

### 2. 文献和笔记共享同一套集合层级

文献库的集合结构在笔记视图下保持一致。  
笔记沿用文献库的集合层级，文献笔记和原论文一一对应。

### 3. Agent 直接操作本地知识库

Agent 直接操作本地知识库：

- 检索文献、读 PDF、写笔记
- 读写文件、跑脚本、操作浏览器
- 定时任务、后台任务、长期记忆

### 4. 本地优先

- 数据默认在本地 SQLite
- 可配 Ollama 完全离线
- 多设备同步是可选能力，走端到端加密

## 功能边界

- **团队协作**：当前面向个人知识库，没有 Notion 式的共享空间/权限体系
- **移动端**：当前只有桌面端
- **纯 Markdown 笔记的插件生态**：不如 Obsidian 成熟
- **论文引用格式/Word 插件**：不如 Zotero 完整
- **扫描版 PDF**：没有文字层时，文本抽取会受限

## 选型建议

- 你只需要一个 Markdown 编辑器
- 你的核心需求是团队协作和数据库
- 你主要用 Word 写论文，且依赖 Zotero 的引文样式
- 你不想在本地管理模型/API Key

## 组合使用也合理

很多人的实际工作流是：

```text
Zotero 管理文献元数据
→ 思库读 PDF、做笔记、让 Agent 整理
→ 需要投稿时再用 Zotero/Word 处理引文格式
```

思库可以和现有工具组合使用，把“读、问、记、追踪”放在一个本地知识库里。
